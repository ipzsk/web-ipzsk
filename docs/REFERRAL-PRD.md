## 1．目标和第一版边界

让普通注册用户可以分享平台，为自己**直接带来的新用户**获得充值佣金。第一版只做一级，不设代理层级、团队业绩或人数奖励。所有推广者统一按有效实付金额的 **5%** 计佣；上线运行满 3 个月后，再用真实付费、复购、成本和退款数据讨论是否调整比例。当前没有自动升级至 10% 的承诺。

这里的“终身”指推荐关系在账户存续期间不因后来点击其他链接而改变；只要该直接推荐客户后续产生符合规则的付款，就继续按当时适用的规则计佣。它不表示推广者拥有客户账户、客户资料或客户的间接推荐关系。

第一版明确不做：多级分成、下线人数奖、付费取得推广资格、首单之外额外奖励、人工补绑老用户、手填邀请码、推广者之间转让客户、自动调整佣金比例。

## 2．用户流程

1. 每个成功注册的用户自动拥有专属推广链接，不需付费、人工申请或先充值。用户在自己的推广中心复制链接；是否另设首次启用时的条款确认，见第 8 节。
2. 新访客打开推广链接并**通过该链接完成注册**时，系统记录这次注册所用链接的推广者。没有完成注册，不建立推荐关系。已有账户再次打开链接，不重新归因。
3. 若访客先打开 A 的链接，后来打开 B 的链接，并最终通过 B 的链接注册，则 B 是唯一推荐者。注册成功后，用户再打开其他推广链接，不改变关系。推广者不能推荐自己。
4. 被推荐人也自动获得自己的推广链接，可以继续推荐别人，但这不会给原推荐者带来第二级收入。例如 A 推荐 B，B 推荐 C：B 的有效充值只给 A 计佣；C 的有效充值只给 B 计佣。
5. 推广者在推广中心看到自己的链接、直接推荐产生的统计、佣金流水与结算状态。被推荐人不显示自己的推荐者。推广者不查看被推荐人的完整身份、提示词、生成内容或间接推荐业绩。

## 3．计佣与结算

| 项目 | 第一版规则 |
| --- | --- |
| 佣金比例 | 统一 5%；按每笔付款发生时的规则计算，不因后续评审追补或追减历史有效订单。 |
| 计佣对象 | 直接推荐客户在平台产生的真实、成功、可核实的充值付款；同一付款只计一次。 |
| 计佣基数 | 客户折扣后实际支付的商品金额，剔除单列代收税费及退款部分；赠送额度、佣金转使用额度、失败或测试订单不计佣。支付通道手续费是否从基数再扣，见第 8 节。 |
| 观察期 | 付款确认后先记待结算佣金；满 30 天、对账完成、没有已知退款或争议，才转为可结算。 |
| 结算频率 | 每月集中处理已符合条件的申请；“每月哪一天”待运营与财务确认。 |
| 最低现金提现 | 单次申请至少 ¥100，且不得超过可结算佣金。未达到门槛的佣金继续累计。 |
| 另一种领取方式 | 推广者可以选择把可结算佣金转为平台使用额度。转换比例、是否允许不足 ¥100 时转换和税务处理见第 8 节。已转换的同一笔佣金不再现金打款，转换本身不产生新佣金。 |

示例：B 通过 A 的链接注册并实付充值 ¥100，在没有折扣和单列税费的例子中，为 A 记录 ¥5 待结算佣金。B 使用充值额度生成内容时不再次计佣。B 后来推荐 C，C 实付充值 ¥100，则为 B 记录 ¥5，A 对 C 的订单得 ¥0。

“满 30 天／已归档”是**本站内部的佣金可结算状态**，不能写成支付永远不可撤销。Waffo 的[开发者条款](https://www.waffo.ai/en/developer-terms)仍规定支付渠道可能处理后续退款和拒付。若结算后发生撤销，账本保留原订单与已付记录，另记冲销或待追回金额，不删除历史。具体追回流程在上线前由财务确认。

## 4．提现及收款信息

用户注册和取得推广链接时，不要求提交银行卡。申请现金提现时再收集完成付款所需的信息，例如收款人姓名、国家／地区、币种与收款账号，并核对收款人与申请者身份。仅有使用额度转换需求的用户，不为提现而采集收款账号。金融账户属于敏感个人信息，应按付款所需最小范围处理，限制访问并避免在日志中明文输出。[《个人信息保护法》](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)

Starryblu、Wise 和境外银行账户只是**候选收款方式**，不是第一版已确定可用的渠道。上线前需核查经营主体、付款来源、收款人地区、币种、手续费、汇率及收款限制，并完成真实的小额到账测试。推广者佣金以人民币记账；跨境付款的换汇口径及手续费承担方须在正式开放前明确。不得假定收款平台 Waffo 会自动替本站向推广者分账。

## 5．异常与对账

对自我推荐、控制多个账号互相推荐、虚假交易、利用退款或其他方式套利等异常情况，可以暂停相关佣金的结算，保留证据并人工核查；确认异常后取消**相关订单**的佣金，记录原因、处理人、时间及申诉结果。不能仅因共用 IP 就直接判定作弊，也不以“最终解释权归平台”代替可核查的处理规则。

后台需要按订单对上：支付方已确认的实付与税费、账户充值入账、直接推荐关系、佣金计提、退款／拒付、可结算余额、使用额度转换和实际打款。支付成功页面、浏览器参数或截图不能单独作为入账和计佣依据。

## 6．第一版验收口径

1. A→B→C：A 只从 B 的有效付款获得 5%，B 只从 C 的有效付款获得 5%，A 从 C 获得 ¥0。
2. 先点 A、最终通过 B 的链接注册：只绑定 B；注册后点击 A，不改绑。
3. 付款 ¥100 的单笔有效订单，只产生 ¥5 待结算佣金；重复支付通知不增加第二笔佣金；使用充值额度不再计佣。
4. 未满 30 天、未完成对账或存在争议的佣金，不进入可结算；满 30 天后可结算，但保留后续撤销的冲销能力。
5. 可结算余额 ¥99.99 时不能申请现金提现；余额至少 ¥100 时可以申请，成功后不能再次提现或转换同一金额。
6. 推广中心不显示间接客户业绩，也不泄露被推荐人的个人资料和创作内容。

## 7．三个月复盘

从**分佣功能正式上线且开始记录真实订单**起计算运行期，满 3 个月后讨论下一版。复盘至少看：直接推荐注册与有效付费人数、每位推广者带来的实付、30 天内及之后的复购、退款与拒付、佣金支出、API／服务成本、赠送成本和每组客户的实际贡献。没有这些数据，不预设升级阶梯。

## 8．上线前待确认，不由 Agent 自行补齐

1. 推广链接的具体 URL／参数，以及注册失败后重试、跨设备或中途离开再回来时是否保留来源；已确认的核心是**注册时使用的链接归因**，不是永久首次点击归因。
2. 推广条款首次确认的时点；不改变“人人自动取得链接、无人工申请”的决定。
3. 实付金额的税费字段映射、部分退款的分摊方式，以及不足 1 分的佣金舍入规则。
4. 月度打款日、提现申请截止日、收款渠道、付款主体、跨境汇率与费用、身份及税务流程。
5. 佣金转使用额度的转换比例、最低转换金额、转换后额度的适用范围，以及发生后续拒付时的处理方式。
6. Waffo 或当前真实支付通道的生产状态、可取得的事件与退款／争议状态；必须以当前代码和支付账户验证，不使用旧部署文档推断。

## 9．项目资料与变更规则

仓库现有的 `docs/DEPLOYMENT.md` 是较早的 AllValue 兑换码方案，**不代表本次讨论后的支付系统现状**；共享对话中的实现宣称也不是本仓库的当前代码事实。研发开始前先核对实际代码、线上支付和账本，再写实现计划。本文只确认分佣产品规则，不确认分佣已实现或支付已投产。

任何评审改动需记录：日期、决策人、改了哪条、原因、影响的订单范围和版本。同步更新本文与 Agent 交接文件；历史订单按产生时的有效规则保留，不静默改写。
