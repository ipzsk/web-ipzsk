# IPZSK API 消费分佣方案

版本：2026-10-12。本文替代 2026-10-10 的利润分佣算法；实现、生产迁移和真实资金验收分别记录。

## 活动周期

分佣活动在管理员首次启用时开始，截止时间为开始时间加一年。暂停后再次启用沿用原截止时间，不延长活动。过期后停止新请求计佣，续期需要新的明确方案。

## 邀请与身份

每个已注册用户可取得直接邀请链接。新用户注册前 30 天内最后一次有效邀请归属生效，注册后固定。BD 和开发者由平台审核开通，身份变化只影响后续消费。自邀请和自消费不产生自身收益。

被邀请人累计已到账的真实充值减退款，严格超过 10 元时，邀请人获得一次有效的 5 元奖励；等于 10 元不发。奖励观察 30 天，退款跌破门槛时冲回，重新达标恢复同一份奖励。

## API 消费分佣

平台按模型 token 及图片、视频、语音等接口的实际计量收费。充值只增加使用余额，分佣在请求成功扣费后计提。Skill 不收启动费或固定调用费。

设退款和拒付后的有效付费 API 消费为 `E`：

- BD 收益：`E × 20%`
- 插件开发者收益：`E × 35%`

两份收益独立计算并按 8 位小数截取。赠送额度、邀请奖励、管理赠额和收益转入余额对应的消费不计佣。没有 BD 时只产生开发者收益；没有插件作者归属时只产生 BD 收益。

| 消费来源 | BD | 插件开发者 |
| --- | ---: | ---: |
| 100 元有效付费消费 | 20 元 | 35 元 |
| 80 元付费余额 + 20 元赠额 | 16 元 | 28 元 |
| 100 元赠额 | 0 元 | 0 元 |

上游实际成本继续记录，用于平台毛利、定价和账单核对。成本未知或后续修正不会阻塞、增加或减少两类分佣。平台需要监控上游成本，避免 55% 总分佣造成负毛利。

## Skill 与插件归属

每笔 API 请求最多归属一个插件作者。Skill 的多次模型调用逐次计佣；生图和视频插件独立调用的费用归该插件作者。客户端上报 Skill 名称和内容哈希，网关校验登记版本、插件凭证、启用状态及模型权限，客户端不能指定收款人或比例。

同轮出现多个作者候选时，后台保存 `ambiguous` 状态，不自动拆分开发者份额。组合作者分配需要独立方案。

## 收益余额与月结

收益观察 30 天，无退款和争议后可用。上月已成熟收益在每月 1–5 日审核，15 日人工转账。单笔提现至少 100 元。

收益可从 0.01 元起按 1:1 转平台使用余额；转入不可逆，不能再次提现，使用这部分余额产生的消费不分佣。提现申请预留金额，取消时解冻。

## 退款与争议

服务退款按原消费的付费和赠送来源退回。全额退款冲回全部相关分佣；部分退款按剩余有效付费消费重新计算。拒付沿原充值来源追溯消费并冲回收益；已转余额或已提现的收益形成负余额，用后续收益抵扣。

历史余额来源未确认、支付争议和不确定入账结果进入人工核对。分佣、退款和提现写入幂等流水并与审计记录放在同一数据库事务中。

## 当前研发状态

后端已实现一年活动期、20%／35% 快照、直接邀请、来源分配、退款和拒付冲回、BD 管理、收益转余额及人工提现。网站和管理台展示当前比例及活动期。生产启用前须完成历史账户资金来源核对；真实支付、退款和人工打款仍需生产验收。
