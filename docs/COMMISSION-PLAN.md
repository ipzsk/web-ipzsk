# IPZSK API 消费分佣方案

版本：2026-10-12，对应后端 schema 32。本文替代 2026-10-10 的利润分佣算法及 schema 31 的一年活动期；规则不设期限，管理员开关是唯一运营开关。实现、生产迁移和真实资金验收分别记录。

## 邀请与身份

每个已注册用户可取得直接邀请链接。新用户注册前 30 天内最后一次有效邀请归属生效，注册后固定。自邀请和自消费不产生自身收益。

BD 和插件开发者只能由管理员邀请开通（后端 schema 33），没有自助申请入口，管理员也不能按用户 ID 直接开通。管理员按已验证邮箱或用户 ID 发起邀请，链接 7 天有效、只能由被邀请账号登录后使用一次；明文链接只在创建或重发时显示，令牌位于 `/account#invite=` 片段，不进入服务器日志。身份变化只影响后续消费，已有身份和历史账本保留。

网站页面：`/account` 的“身份与邀请”显示 BD／开发者状态与待接受邀请，并负责接受邀请；`/#wallet` 的“邀请与收益”显示当前身份、邀请链接与人数、按来源累计分佣、逐笔流水、转余额和提现；`/developer` 显示自己归属的插件、用量收益和同一收益账户的开发者视图。

被邀请人累计已到账的真实充值减退款，严格超过 10 元时，邀请人获得一次有效的 5 元奖励；等于 10 元不发。奖励观察 30 天，退款跌破门槛时冲回，重新达标恢复同一份奖励。

## API 消费分佣

平台按模型 token 及图片、视频、语音等接口的实际计量收费。充值只增加使用余额，分佣在请求成功扣费后计提。Skill 不收启动费或固定调用费。

设退款和拒付后的有效付费 API 消费为 `E`，归属于付费部分的可信实际上游成本为 `C×q`（`q` 为扣款时本金占比）：

- BD 收益：`B = E × 20%`
- 插件开发者收益：`max(E − C×q − B, 0) × 40%`；没有 BD 时 `B` 记为 0

每项按 8 位小数截取，尾差留平台。赠送额度、邀请奖励、管理赠额和收益转入余额对应的消费不计佣。没有插件作者归属时只产生 BD 收益。

| 消费来源（实际成本 40 元） | BD | 插件开发者 |
| --- | ---: | ---: |
| 100 元付费，有 BD | 20 元 | 16 元 |
| 100 元付费，无 BD | 0 元 | 24 元 |
| 80 元付费 + 20 元赠额 | 16 元 | 12.8 元 |
| 100 元赠额 | 0 元 | 0 元 |

实际成本只取可信上游账单，估算值和缺失成本不当作实际成本或 0。成本未知时 BD 收益照常计提，开发者收益保持待成本，确认后补计；成本修正只追加开发者差额，BD 不变。成本达到或超过 `E − B` 时开发者为 0，BD 照常计提。

用户接口 `GET /api/me/commissions` 的 `policy` 只返回 `bd_share_bps`、`developer_share_bps`、`developer_basis`（固定 `remaining_profit`）和 `active`，不再返回活动开始／截止时间。

## Skill 与插件归属

每笔 API 请求最多归属一个插件作者。Skill 的多次模型调用逐次计佣；生图和视频插件独立调用的费用归该插件作者。客户端上报 Skill 名称和内容哈希，网关校验登记版本、插件凭证、启用状态及模型权限，客户端不能指定收款人或比例。

同轮出现多个作者候选时，后台保存 `ambiguous` 状态，不自动拆分开发者份额。组合作者分配需要独立方案。

## 收益余额与月结

收益观察 30 天，无退款和争议后可用。上月已成熟收益在每月 1–5 日审核，15 日人工转账。单笔提现至少 100 元。

收益可从 0.01 元起按 1:1 转平台使用余额；转入不可逆，不能再次提现，使用这部分余额产生的消费不分佣。提现申请预留金额，取消时解冻。

## 退款与争议

服务退款按原消费的付费和赠送来源退回。全额退款冲回全部相关分佣；部分退款按剩余有效付费消费重新计算，付费部分承担的上游成本不变。拒付沿原充值来源追溯消费并冲回收益；已转余额或已提现的收益形成负余额，用后续收益抵扣。

历史余额来源未确认、支付争议和不确定入账结果进入人工核对。分佣、退款和提现写入幂等流水并与审计记录放在同一数据库事务中。

## 当前研发状态

后端 schema 32 已实现永久 BD 20%／开发者剩余利润 40% 快照、成本待定与补计、直接邀请、来源分配、退款和拒付冲回、BD 管理、收益转余额及人工提现；schema 31 期间的请求保留原 35% 消费口径快照。网站展示当前比例、启用状态及剩余利润口径。schema 33 增加管理员邀请制的 BD／开发者开通、撤销、重发、过期与审计，网站增加邀请接受与按身份区分的收益视图。生产启用前须完成历史账户资金来源核对；真实支付、退款和人工打款仍需生产验收。
